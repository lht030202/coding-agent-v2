# Agent 循环 · 说明

本部分是全书九个部分中的第三个，属于第一阶段"打基础"的收尾。上一部分讲了怎么调一次模型，本部分讲怎么把多次调用串成一个能自己推进任务的循环。

---

## 一、为什么把 Agent 循环单独成部分

普通的 LLM 应用是"问一次、答一次"。Agent 的区别在于：模型自己决定下一步做什么，代码执行之后把结果交回模型，如此循环，直到任务完成。

这个循环是 Agent 的骨架。面试里"讲讲你的 Agent 架构"，问的就是它。

---

## 二、本部分的内容

- 第一篇《ReAct 与 Plan-and-Execute》：一步一想的 ReAct 循环，先规划再执行的模式，以及停止条件怎么设计。
- 第二篇《LangGraph 编排与状态》：节点、边、条件边和状态；本项目的图怎么搭；为什么用图而不是 while 循环。

---

## 三、学习目标

读完本部分后，你应当能够说清五件事。

- ReAct 循环每一步做什么，本项目的 act → verify 怎么对应它。
- 本项目为什么先 plan 再 act，这样做的好处和代价。
- 循环什么时候停（调用 finish、步数达到上限），以及为什么必须有步数上限。
- 本项目的图有哪些节点和边，唯一的循环是怎么形成的；能凭记忆把图画出来。
- 用图和用 while 循环各有什么好处，什么时候才值得用 LangGraph。

---

## 四、使用建议

先对照第一次运行的轨迹（12 个事件）读 `graph.py` 的 `build()`，再按事件顺序读各个节点。

有一处需要分清：原版的 verify 只"判断要不要停"，不"检查结果对不对"，它写下的 note 模型也看不到。新版的测试验证模式（`CC_AGENT_VERIFY_MODE=tests`）会在结束前自动跑测试，失败就把报错交回模型，见[《改进说明》第 2 条](../../改进说明.md)。

---

## 五、练习与自测

- **第一项，三道读代码题。**
  1. 如果模型某一步回复的不是 JSON，而是一段普通文字，会发生什么？任务最后以什么状态结束？
  2. "最多 8 步"在哪里设置？又在哪里判断"步数用完"？
  3. 想让 Review 发现问题时打回 act 重做，`build()` 里要改哪一行？怎么防止无限打回？
- **第二项，画图。** 不看代码画出本项目的流程图，标出唯一的条件分支，再和 `build()` 对照。
- **自测：** 用一分钟回答"讲讲你的 Agent 是怎么工作的"。
