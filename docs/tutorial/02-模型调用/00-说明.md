# 模型调用 · 说明

本部分是全书九个部分中的第二个，属于第一阶段"打基础"的开头。Agent 的一切行为都从"调一次模型"开始：规划、选工具、审查、总结，底层用的都是同一个函数。

---

## 一、为什么把模型调用单独成部分

- 它是 Agent 和模型之间唯一的接口。整个项目只有 `llm.py` 直接调模型，第一次运行的 7 次调用全部经过它。
- 面试高频问题集中在这一层：OpenAI 兼容接口、消息角色、无状态、thinking 模式、token 成本。
- 后面的 function calling 改进，也要从这一层动手。

---

## 二、本部分的内容

- 第一篇《OpenAI 兼容接口与消息结构》：客户端怎么建，messages 怎么组织，为什么说调用是无状态的。
- 第二篇《thinking 模式与 token 成本》：thinking 是什么，Agent 里为什么要关，各家的扩展参数怎么传，token 和耗时怎么记录。

第一篇以原版的 `llm.py` 为例（只返回文本）。新版把它扩展成支持工具调用、能记录 token 的 `LLMResult`，改动见[《改进说明》第 4 条](../../改进说明.md)。

---

## 三、学习目标

读完本部分后，你应当能够说清四件事。

- 为什么换模型供应商只需要换 `base_url` 和模型名；以及"OpenAI 兼容"在哪里并不兼容（扩展参数各家不同）。
- system 和 user 消息分别放什么；为什么说 LLM 调用是无状态的，Agent 的"记忆"从哪来。
- thinking 模式对速度、成本和 Agent 行为的影响，以及本项目为什么选择关掉它。
- 一次调用的 token 用量和耗时从哪里拿到、记到哪里，它们服务于哪些指标。

---

## 四、使用建议

先运行 `playground/try_llm.py` 建立直觉，再读 `llm.py`，最后做练习。

有两处容易混淆：

- `max_tokens` 限制的是**输出**长度，不是上下文长度。
- thinking 的思考内容也计入输出 token。连通测试里 64 个输出 token 有 45 个是思考。

---

## 五、练习与自测

- **第一项，追踪一个配置。** 新版已经关掉了 thinking。从 `.env` 里的 `OPENAI_EXTRA_BODY` 出发，找出它经过哪几个函数，最后怎样出现在接口请求里。（提示：`config.py` 的 `parse_extra_body` → `llm.py` 的 `chat`）
- **第二项，看懂成本。** 跑一次示例任务，再用 `run_agent.py stats` 汇总轨迹，说出这次任务的模型调用次数、输入和输出 token、模型耗时，并在轨迹文件里找到对应的 `llm_call` 事件。
- **自测：** 不看代码，说出原版 `complete()` 发给模型的两条消息分别是什么、丢掉了返回里的哪两样信息，以及新版的 `LLMResult` 把它们补在了哪里。

---

## 六、与全书的关系

- 本部分是第三部分"Agent 循环"的地基：plan、act、review、summarize 四个节点都通过 `_call_llm` 调用 `llm.py` 的 `chat()`，区别只在 system prompt 和是否带工具。
- 第四部分"工具系统"的原生 function calling，就是在 `chat()` 上多传一个 `tools` 参数。
- 本部分记录的 token 和耗时，是第八部分"评测体系"和第九部分"可观测性"的数据来源。
